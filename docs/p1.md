# Parte 1: K3s e Vagrant

Status atual: o [`p1/Vagrantfile`](../p1/Vagrantfile) sobe duas VMs Debian 13 com IP fixo e SSH só por chave ([`scripts/ssh.sh`](../p1/scripts/ssh.sh)), e roda os stubs [`scripts/server.sh`](../p1/scripts/server.sh) e [`scripts/worker.sh`](../p1/scripts/worker.sh), que só registram o papel de cada máquina. A box Debian é construída por nós com Packer ([`scripts/build.sh`](../p1/scripts/build.sh)) e publicada num GitHub Release, de onde o `vagrant up` a baixa. A instalação do K3s ainda está pendente (issues seguintes do milestone P1).

> Validado no homelab (Ubuntu 24.04, Celeron J1800): build da box, download da box pelo release, `vagrant up` das duas VMs, nomes, IPs (`enp0s8`, separada da NAT `enp0s3`), ping nos dois sentidos entre as VMs, 1 CPU, ~1 GB de RAM e sem swap em cada uma.

## O que o Vagrantfile cria

| Máquina | Papel (futuro) | IP | Recursos |
|---------|----------------|----|----------|
| `<login>S` | K3s server (controller) | `192.168.56.110` | 1 CPU, 1024 MB |
| `<login>SW` | K3s agent (worker) | `192.168.56.111` | 1 CPU, 1024 MB |

- Box: **Debian 13 "trixie"** (amd64), construída por nós com Packer. O Vagrantfile declara a origem em `config.vm.box_url`, que aponta para o [release `box-debian-13.7.0`](https://github.com/northwindstudios/inception-of-things/releases/tag/box-debian-13.7.0) deste repositório (~420 MB), com `box_download_checksum` SHA256. O primeiro `vagrant up` baixa a box; não é preciso rodar o build.
- Provider: **só VirtualBox**. O subject deixa o provider livre; escolhemos o mesmo do exemplo dele, e a avaliação normalmente roda VirtualBox. Um único provider também dá um único caminho para testar.
- `LOGIN` no topo do Vagrantfile é o **login da 42** (dá o nome às máquinas), não o usuário SSH. Dentro das VMs o usuário é sempre `vagrant`.
- A pasta compartilhada `/vagrant` está desligada. Os scripts chegam às VMs via provisioner (`shell` com `path:`), que faz upload por SSH.

## Rede privada

Cada VM tem duas interfaces:

| Interface | Tipo | Endereço |
|-----------|------|----------|
| `enp0s3` | NAT do VirtualBox (saída para a internet) | `10.0.2.15` |
| `enp0s8` | `private_network`, dedicada ao cluster | `192.168.56.110` (server) / `192.168.56.111` (worker) |

- Os nomes das interfaces são preditivos (a box não usa `net.ifnames=0`), então a interface dedicada **não** é `eth1`. Nenhum script deve fixar o nome: use o IP ou descubra a interface com `ip a`. O K3s será configurado com o IP/interface nas issues de instalação.
- A faixa `192.168.56.0/21` é liberada por padrão pelo VirtualBox, então não precisa de `/etc/vbox/networks.conf`.

Verificação (com as VMs de pé):

```bash
vagrant ssh <login>S  -c 'ip -br -4 a; ping -c 3 192.168.56.111'
vagrant ssh <login>SW -c 'ip -br -4 a; ping -c 3 192.168.56.110'
```

Esperado: `enp0s3` com `10.0.2.15`, `enp0s8` com o IP da própria VM e 0% de perda no ping.

## SSH sem senha

O subject pede `vagrant ssh <login>S` e `vagrant ssh <login>SW` sem senha. O `vagrant ssh` usa chave:

- A box traz a chave insegura pública do Vagrant. No primeiro boot, o `insert_key` padrão a troca por uma chave única por VM. A chave privada fica em `p1/.vagrant/machines/<vm>/virtualbox/private_key`, ignorada pelo git. Nenhuma chave nem senha é commitada.
- [`scripts/ssh.sh`](../p1/scripts/ssh.sh) roda em todas as VMs, antes dos scripts de cada papel, e fecha o resto: desliga `PasswordAuthentication` e `KbdInteractiveAuthentication`, bloqueia o login de root e trava a senha do `vagrant`. A senha `vagrant` do preseed só serve para o Packer entrar durante o build da box. O sudo sem senha do `vagrant` continua.
- O arquivo de configuração é `/etc/ssh/sshd_config.d/10-iot.conf`. O prefixo `10-` faz o sshd ler esse arquivo antes do `99-vagrant.conf`, porque vale o primeiro valor lido.

Verificação:

```bash
vagrant ssh <login>S  -c 'hostname'     # abre sem pedir senha
vagrant ssh <login>SW -c 'hostname'
vagrant ssh <login>S -c 'sudo sshd -T | grep -E "^(passwordauthentication|kbdinteractiveauthentication|permitrootlogin) "; sudo passwd -S vagrant'
# no, no, no e status L (senha travada)
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password vagrant@192.168.56.110   # Permission denied (publickey)
```

## Por que construímos a box com Packer

O subject exige que o Vagrantfile diga de onde vem a box (`box_url`), com uma imagem publicada pela própria distribuição ou uma box construída por nós, porque o registry da HashiCorp não é garantido depois de 2026.

- O Debian não publica `.box` próprio. A `debian/trixie64` do Vagrant Cloud é mantida pelo time do Debian, mas só tem o provider **libvirt**, não VirtualBox.
- O Rocky Linux 10 publica box VirtualBox oficial, mas exige CPU **x86-64-v3** (AVX2, BMI, FMA). No homelab (Celeron J1800, 2013) a VM trava no boot com `gurumeditation`. O Debian roda em qualquer x86-64.
- Então construímos a box do Debian 13 a partir da **ISO oficial** (netinst, com checksum SHA256 fixado).

### Como a box é construída

| Arquivo | Função |
|---------|--------|
| [`p1/scripts/build.sh`](../p1/scripts/build.sh) | Roda `packer init` e `packer build`; remove do cache do Vagrant qualquer box `debian13` antiga. |
| [`p1/confs/packer/debian-13.pkr.hcl`](../p1/confs/packer/debian-13.pkr.hcl) | Template do Packer: ISO, recursos da VM de build, `boot_command`, pós-processador `vagrant`. |
| [`p1/confs/packer/http/preseed.cfg`](../p1/confs/packer/http/preseed.cfg) | Respostas do instalador do Debian (instalação sem intervenção, usuário `vagrant`, uma partição ext4 **sem swap**). |
| [`p1/confs/packer/provision.sh`](../p1/confs/packer/provision.sh) | Dentro da VM de build: chave SSH do Vagrant, `UseDNS no`, limpeza e **zerar o espaço livre** (a box cai de ~830 MB para ~420 MB). |

Sem swap porque o kubelet do K3s se recusa a subir com swap ligada por padrão. A linha `dd: error writing '/EMPTY': No space left on device` no log do build é esperada: é o zero-fill chegando ao fim do disco.

O resultado é `p1/boxes/debian-13-virtualbox.box` (ignorado pelo git, como todo `*.box`).

- O build baixa a ISO (~790 MB), instala o Debian pela rede e gera uma box de ~420 MB. No homelab (Celeron J1800) levou **cerca de 40 minutos**.
- **Só é necessário rodar o build para mudar a box** (template, preseed, `provision.sh` ou ISO). Quem só quer subir as VMs usa a box publicada no release.
- A URL da ISO usa `.../iso-cd/` (`current`), que guarda só a versão pontual mais recente. Quando o Debian lançar a próxima (13.8, por exemplo), o download falha: atualize `iso_url` e `iso_sha256` no template (os checksums estão no `SHA256SUMS` da mesma pasta).

### Publicando uma box nova

Depois de reconstruir e validar a box localmente:

```bash
BOX_URL="file://$PWD/boxes/debian-13-virtualbox.box" vagrant up   # testa a box local (sem checksum)
shasum -a 256 boxes/debian-13-virtualbox.box
gh release create box-debian-<versão> boxes/debian-13-virtualbox.box --title "..." --notes "..."
```

Depois atualize `BOX_URL` e `BOX_SHA256` no `Vagrantfile`. Use um tag novo por versão, em vez de sobrescrever o arquivo de um release existente, para não quebrar quem já fixou o checksum antigo. Releases de arquivos grandes não têm custo no GitHub (limite de 2 GiB por arquivo).

## Vagrant não é Ansible

O Vagrant **cria** VMs num hypervisor local e depois as provisiona. Ele não configura servidores que já existem (isso é Ansible). Por isso o p1 tem que rodar numa máquina com hypervisor; VPS existentes só servem como **host** do Vagrant, e precisam de virtualização aninhada e recursos para duas VMs de 1 GB.

## Rodando no Ubuntu 24.04 (homelab)

Host de teste: Ubuntu 24.04, bare metal, x86_64 com VT-x, 3,5 GiB de RAM. Duas VMs de 1 GB cabem, com pouca folga; se apertar quando o K3s entrar, o worker pode cair para 512 MB (o subject permite).

Instalação (uma vez):

```bash
# Vagrant e Packer da HashiCorp (os pacotes do Ubuntu são antigos)
wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp.gpg
echo "deb [signed-by=/usr/share/keyrings/hashicorp.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" \
  | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install -y vagrant virtualbox
sudo apt install -y packer   # só se for reconstruir a box
vagrant --version; VBoxManage --version
```

Versões usadas: Vagrant 2.4.9, Packer 1.16.2, VirtualBox 7.0.16.

Uso:

```bash
cd p1
vagrant validate
vagrant up                # no primeiro uso baixa a box (~420 MB) do release
vagrant up
vagrant status
vagrant ssh <login>S  -c 'hostname; nproc; free -m | head -2; cat /etc/debian_version'
vagrant ssh <login>SW -c 'hostname; nproc; free -m | head -2; cat /etc/debian_version'
vagrant destroy -f
```

> **Nunca rode o Vagrant com `sudo`.**

### Rodando num host remoto (SSH)

Sincronize a pasta sem apagar o estado das VMs nem a box já construída:

```bash
rsync -a --delete --exclude .vagrant/ --exclude boxes/ --exclude confs/packer/output/ \
  p1/ <user>@<host>:~/inception-of-things/p1/
```

Se for reconstruir a box: o build leva tempo e morre se a sessão SSH cair. Rode-o desacoplado e acompanhe o log:

```bash
cd ~/inception-of-things/p1
(setsid nohup ./scripts/build.sh > ~/packer-build-p1.log 2>&1 < /dev/null &)
tail -f ~/packer-build-p1.log
```

Para ver a tela do instalador durante o build: `VBoxManage controlvm debian-13 screenshotpng /tmp/tela.png`.

## Troubleshooting

### O `vagrant up` falha ao baixar a box ou com erro de checksum

Confira se o release `box-debian-13.7.0` ainda existe e se `BOX_SHA256` no `Vagrantfile` é o SHA256 do arquivo anexado. Para usar uma box construída localmente: `BOX_URL="file://$PWD/boxes/debian-13-virtualbox.box" vagrant up`.

Se uma box `debian13` antiga ficou no cache do Vagrant, remova com `vagrant box remove --all debian13`.

### O build do Packer falha ao baixar a ISO

O Debian moveu a ISO para o arquivo quando saiu uma nova versão pontual. Atualize `iso_url` e `iso_sha256` em `confs/packer/debian-13.pkr.hcl`.

### `The private key ... must be owned by the user running Vagrant`

Alguém rodou `sudo vagrant up` e o `.vagrant/` ficou com dono `root`. Para corrigir:

```bash
sudo vagrant destroy -f
sudo rm -rf .vagrant
vagrant up   # sem sudo
```

### VirtualBox não sobe VM (`vboxdrv` não carregado, `VERR_VMX_IN_VMX_ROOT_MODE`)

- Com Secure Boot ligado, o módulo `vboxdrv` precisa ser assinado e a chave registrada via `mokutil` (o `apt` pede uma senha de MOK; confirme no próximo boot). Cheque com `mokutil --sb-state`.
- O KVM carregado (`kvm_intel` / `kvm_amd`) toma o VT-x. Descarregue com `sudo modprobe -r kvm_intel kvm` (ou `kvm_amd`) e, para ficar permanente, faça blacklist ou use `kvm.enable_virt_at_load=0` no GRUB.
- Se o Vagrant não reconhecer a versão do VirtualBox do Ubuntu, instale o VirtualBox do repositório da Oracle.

### VM em `gurumeditation` logo no boot

Em geral é a CPU do host sem as instruções que a imagem exige (foi o caso do Rocky Linux 10 no homelab). Confira os flags com `grep -m1 flags /proc/cpuinfo` e veja o `VBox.log` em `~/VirtualBox VMs/<vm>/Logs/`.
