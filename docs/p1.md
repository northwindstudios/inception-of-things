| Máquina | Papel (futuro) | IP | Recursos |

| `<login>S` | K3s server (controller) | `192.168.56.110` | 1 CPU, 1024 MB |
| `<login>SW` | K3s agent (worker) | `192.168.56.111` | 1 CPU, 1024 MB |

- Box: `debian/trixie64` (Debian 13, amd64). A imagem é baixada no primeiro `vagrant up`; não precisa de ISO.
- `LOGIN` no topo do Vagrantfile é o **login da 42** (dá o nome às máquinas), não o usuário SSH. Dentro das VMs o usuário é sempre `vagrant`.
- Tem configuração para os providers `libvirt` e `virtualbox`.
- A pasta compartilhada `/vagrant` está desligada (ver [Troubleshooting](#nfs-connection-refused-ao-montar-vagrant)). Scripts devem chegar às VMs via provisioner (`shell` com `path:` ou `file`), que faz upload por SSH.

## Vagrant não é Ansible

O Vagrant **cria** VMs num hypervisor local e depois as provisiona. Ele não configura servidores que já existem (isso é Ansible). Por isso o p1 tem que rodar numa máquina com hypervisor; VPS existentes só servem como **host** do Vagrant, e precisam de virtualização aninhada e recursos para duas VMs de 1 GB.

## Rodando no Linux (Fedora) com libvirt

Testado no Fedora 44 com `vagrant-2.3.4` e `vagrant-libvirt-0.11.2` dos repositórios oficiais.

```bash
sudo dnf install vagrant vagrant-libvirt libvirt-daemon-kvm
sudo systemctl enable --now libvirtd
sudo usermod -aG libvirt $USER   # depois: logout/login ou `newgrp libvirt`

cd p1
vagrant up --provider=libvirt
vagrant ssh <login>S  -c 'cat ~/hello-world.txt'   # -> hello-world
vagrant ssh <login>SW -c 'cat ~/hello-world.txt'   # -> hello-world
vagrant destroy -f
```

> **Nunca rode o Vagrant com `sudo`.** Se ele pedir permissão, falta o grupo `libvirt` na sessão (`id -nG` deve listar `libvirt`).

Preferimos libvirt ao VirtualBox no Fedora: o KVM já vem carregado e não há módulo de kernel para compilar nem assinar.

## Rodando no macOS / VirtualBox

> Não testado ainda.

- **Mac Intel (`uname -m` = `x86_64`)**: instalar VirtualBox e Vagrant (versão atual da HashiCorp) e rodar `vagrant up --provider=virtualbox`. A faixa `192.168.56.0/21` é a padrão de host-only do VirtualBox, então os IPs funcionam sem configuração extra.
- **Apple Silicon (`uname -m` = `arm64`)**: a box `debian/trixie64` é só amd64 e **não roda**. É preciso uma box arm64 e um provider compatível (VirtualBox 7.1+, VMware Fusion com `vagrant-vmware-desktop`, ou Parallels com `vagrant-parallels`). Pendente: escolher a box por provider no Vagrantfile.

A avaliação roda na máquina da escola (normalmente VirtualBox), então o Vagrantfile precisa funcionar **lá**, não só nas nossas máquinas.

## Troubleshooting

### `Network 192.168.56.110 is not available`

O `vagrant-libvirt` empacotado no Fedora usa `qemu:///session` por padrão, que não consegue criar a rede privada. Resolvido no Vagrantfile com:

```ruby
node.vm.provider "libvirt" do |v|
  v.qemu_use_session = false   # usa qemu:///system
end
```

Requer o usuário no grupo `libvirt`.

### NFS `Connection refused` ao montar `/vagrant`

No libvirt, a pasta compartilhada padrão usa NFS, e o host precisaria de um servidor NFS e de portas liberadas no firewalld. Como não usamos a pasta, ela está desligada:

```ruby
config.vm.synced_folder ".", "/vagrant", disabled: true
```

### `The private key ... must be owned by the user running Vagrant`

Alguém rodou `sudo vagrant up` e o `.vagrant/` ficou com dono `root`. Para corrigir:

```bash
sudo vagrant destroy -f
sudo rm -rf .vagrant
newgrp libvirt                 # ou logout/login, se ainda não estiver no grupo
vagrant up --provider=libvirt  # sem sudo
```

### VirtualBox no Fedora não sobe VM (`vboxdrv` não carregado)

Combinação de problemas que encontramos com o pacote da Oracle no Fedora 44 (kernel 7.2):

- o módulo `vboxdrv` precisa ser compilado (`kernel-devel` + `sudo /sbin/vboxconfig`);
- com Secure Boot ligado, o módulo precisa ser assinado e a chave registrada via `mokutil`;
- o KVM carregado (`kvm_intel`) toma o VT-x; é preciso descarregá-lo ou usar `kvm.enable_virt_at_load=0`;
- o Vagrant 2.3.4 do Fedora provavelmente não reconhece o VirtualBox 7.2 (seria preciso o Vagrant 2.4.x da HashiCorp).

Por isso usamos libvirt no Fedora.
